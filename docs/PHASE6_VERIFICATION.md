# Phase 6 — Reburn & Recovery Gap verification

Date: 29–30 October 2026. Existing AfterFire repository; no new application, no FIRMS reimport/reset and no fabricated production observations. Earlier phase reports are preserved. This report separates software implementation, controlled fixtures and observed NASA evidence. **A real repeated-burn case is not established by the currently verified 2021–2026 reference history.**

## 1–8. Infrastructure

The initial audit covered FIRMS candidate/detection joins, `recurrence_engine.py`, recovery assessment and comparison, native raster adapters, spatial recovery, source/catalog cache, preflight, persistent jobs, progress/SSE, worker leases, PostGIS, routing and Docker/Nginx. Existing Recurrence mixed candidate intervals with scalar whole-area NDVI and could not establish shared burned ground. The compatibility API now reports candidate context and null shared-area recovery indicators instead of a scalar “Substantially Recovered” conclusion; it exports the new observed engines through the existing module. Stored Phase 3–5 publications are untouched. Existing AppEEARS rehashed annual subset files repeatedly; original HDF reuse had a separate integrity implementation. All routes eagerly loaded into the main frontend bundle. Cleanup protected all temporary files indefinitely and provided no reference audit of published assets.

Implemented one shared persistent integrity policy with native validation retained, cross-process verification locking, manifest/file-generation binding, TTL/validator invalidation, atomic evidence and metrics. Each annual bundle has one persistent manifest snapshot with all file fingerprints; batch readers hold sorted subset writer locks while reusing it. Fixed duplicated planner/downloader checks. [Controlled benchmark](phase6-integrity-benchmark.json): cold 64 MiB hash 0.370571 s; indexed 0.000681 s / zero hash bytes; changed file 0.385206 s; corrupt content rejected; four concurrent readers one hash; new process reuses persisted evidence.

[Final real planner A/B](phase6-planning-benchmark.json): same 168 source candidates, geometry and configuration, three alternating fully warm pairs, zero scientific acquisitions. Median end-to-end legacy 0.6655 s (0.5049–0.8019), manifest index 0.5707 s (0.4903–0.6814). Cache/plan medians are 0.5278 versus 0.5434 s: **no stable cache-stage latency improvement is demonstrated**. Hash bytes deterministically fall from 3,292,870 to zero; all file generations remain checked. The [initial 43.3639→0.9414 s stage comparison](phase6-planning-initial-benchmark.json) also populated HDF evidence and must be read as cold/warm conditions, not an isolated algorithm speedup. Hash counters do not measure all raster/GDAL filesystem reads.

Cleanup now distinguishes A/B persistent scientific and visual assets, C reacquirable sources, D processed checkpoints and E temporary files. It reports total reclaimable versus selected bytes, preserves publications/metadata/hardlinks, checks inode generations and uses the existing exclusive usage/quota locks. Orphan temporary files require a 24-hour grace period and no active usage lease. A new administrator reference audit lists dangling visual assets, equivalent publications and active job folders. Publications are preserved; automatic result deduplication or derived-asset regeneration/deletion is **not implemented**. Destructive scientific-cache tests run only on temporary volumes. During final verification, the system disk fell below the 1 GiB reserve; the pipeline correctly rejected work. Selected unused Docker build-cache records were removed, restoring approximately 1.9 GB free. Database/scientific volumes and active images were preserved; no scientific cache cleanup was performed on production data.

Subset capacity is checked before transfer, with chunk quota checks retained. Preflight exposes available/protected/recoverable bytes. The application cannot reclaim protected publications automatically; exhausted protected storage still requires an administrator quota/policy decision. Native IO cancellation now holds the cache lease until the underlying thread finishes. PostgreSQL connections use pre-ping and recycle; the existing Nginx Docker DNS fix remains. No independent queue was added.

Frontend routes and the Event Analysis Reburn panel are lazy. Initial JS fell from the historical Phase 5 1,015.40 kB / 289.56 kB gzip to 277,914 bytes / 105,707 HTTP gzip bytes; total lazy code still exists. Static assets now support gzip and immutable hash-based caching, while index.html is revalidated and SSE is not compressed/buffered by that asset rule. [Build output](phase6-build-final.log), [browser resource/navigation measurements](phase6-frontend-performance.json). In the final run, the home page transferred 121,970 encoded bytes across eight asset requests; DOM initialization/navigation metrics are in the resource evidence. These browser timings have no isolated old-tree timing baseline; no unsupported initialization-speed claim is made.

## 9–17. Burn reconstruction and real evidence

[Methodology](REBURN_DETECTION_METHODOLOGY.md): strict QA, product-year DOY, uncertainty intervals, stable global native cell IDs, duplicate collapse across subsets/months and configurable spatial/temporal grouping. The repeated-cell count requires the same native ground cell in separate components. Candidate footprints are context; multiple plausible identities remain ambiguous. Each publication records product IDs/checksums, parameters, coverage, source fingerprint, algorithm and timestamp. One additive history table reuses the persistent queue and source publications.

The real reference is `event-4a728489ea44ea85eab6a978870e0b06`, source `2abc3a98d03cd3f51f4c4491f555813afb97fe474ee6b21b590cb0e56eee90b3`. Explicit NASA acquisition covered the existing approximately 20.18 km² observed cell territory for 2021-01-01–2026-10-28. Annual native spatial subsets were retained/resumed; 68 monthly records through August 2026 were available. September/October 2026 remain uncovered. The first worker publication transferred 625,116 scientific bytes; a separate bounded validation prefetch transferred 142,526 bytes for 2025 (2023 prefetch reused completed files). These are distinct transfer counters, not all bytes attributed to one worker.

That history has 94 observed cells, 20.177915 km², two disconnected spatial components in August 2021 (68 and 26 cells), **zero repeatedly burned cells**. Both components overlap in date and share the same FIRMS candidate context; they do not establish two different official fires. No operational threshold was tuned to manufacture repeat burning. Original cell-level dates were corrected in `reburn-6.0.1` to use each cell's own observations rather than component-wide extremes. Development `6.0.0` publications remain versioned and inspectable.

Version `reburn-6.0.2` also tightens mapped-coverage QA: uncertainty must be 0–100 and MCD64A1 special unburned codes (QA bits 5–7) must be zero. Zero observed burns with incomplete mapping remains grey/unknown. All 94 expected native cells remain visible in the 2020 missing-source control across scientific map layers.

## 18–25. Recovery Gap and cumulative observations

Implemented common-cell intersection, nominal and uncertainty-bounded intervals, native VI child aggregation, pre-first-episode seasonal baseline, separate NDVI/EVI indicators, sustained return, persistent anomaly, freshness and missing support. Composites crossing the earliest plausible second-burn date are excluded. Three-plus-episode histories remove cells with intervening burns from the wrong pair. Cell-level maps and the cumulative chart use their actual spatial support; no whole-event mean is assigned to a smaller common area.

The real reference history has no shared cells between temporally distinct burns, so **no real Recovery Gap pair is established there**. No pre-reburn anomaly, return date or ecological conclusion is fabricated to fill this gap. Positive/negative return classifications and temporal leakage protection are numerically verified with fixtures. This is implementation validation, not real-world validation of Recovery Gap accuracy.

[Independent seasonal arithmetic](phase6-vegetation-independent.json) recomputes reference medians/anomalies from persisted observations with no calls to RecoveryGapEngine. [Independent native vegetation check](phase6-native-vegetation-verification.json) rereads NASA integer VI/QA/reliability for 2019-08-13, 2023-03-06 and 2026-09-30, independently decodes QA, reapplies scale 0.0001 and compares all 376 native pixels for NDVI/EVI against the published rasters. Maximum numeric discrepancy is about 2.98e-8, below the explicit 1e-7 float32 tolerance. These checks preserve the original Phase 5 source publication.

Version `reburn-6.0.2` retains the composite schedule, including missing/rejected observations, and adds before-first, between-episode and after-last segments with trend, persistent negative periods and sustained return periods. Temporally overlapping spatial components are grouped before constructing windows. Cell charts never substitute territory averages when cell data are missing. Cumulative observations retain fixed seasonal reference, values, anomalies and QA support. Post-request-cutoff composites are excluded from new results; earlier baseline context is retained. No causal damage score or future risk prediction is added.

```bash
docker compose run --rm --no-deps -v "$PWD/scripts:/scripts:ro" -v "$PWD/backend:/app:ro" backend python -m pytest app/tests -q --disable-warnings -p no:cacheprovider
docker compose run --rm --no-deps -e AF_TEST_DATABASE_URL=postgresql+asyncpg://afterfire:afterfire@db:5432/afterfire_test_phase6 -v "$PWD/scripts:/scripts:ro" -v "$PWD/backend:/app:ro" backend python -m pytest app/tests -q --disable-warnings -p no:cacheprovider
docker compose build backend analysis-worker frontend
node scripts/verify_phase6_browser.mjs
node scripts/verify_phase6_frontend_performance.mjs
# Read-only real checks; evidence mounts are separate from the read-only source mount.
docker compose run --rm --no-deps -e PYTHONPATH=/app -v "$PWD/backend:/app:ro" -v "$PWD/scripts:/scripts:ro" -v "$PWD/docs:/evidence" backend python /scripts/verify_phase6_real.py
docker compose run --rm --no-deps -e PYTHONPATH=/app -v "$PWD/scripts:/scripts:ro" -v "$PWD/docs:/evidence" backend python /scripts/verify_phase6_native_vegetation.py
```

The preparation/prefetch/prior-candidate scripts explicitly acquire or submit NASA tasks; they are not read-only regression checks. Their scope is limited to the documented reference geometry/dates.
